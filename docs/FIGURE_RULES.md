# note の挿絵の基準

この一式の数値と判断の根拠。PLAYBOOK.md から参照される。

## 1. 情報密度 — 挿絵はインフォグラフィックではない【変えない】

**単体で完結する図（インフォグラフィック）と、本文の理解を助ける図（挿絵）では最適な密度が違う。**

挿絵は本文と一緒に読まれる。図だけで全部を語ろうとすると、読者は本文と図の両方を読む羽目になり、
負担が倍になる。年表を6カラムに人物・説明文・キャプションまで詰めた図は、インフォグラフィックとしては
完成度が高くても、記事の挿絵としては重すぎる。

図を1枚作るたびに問う：**「この図は本文の代わりか、本文の補助か」**。
補助なら、本文が言っていることを図で繰り返さない。**図でしか言えないことだけを描く。**

> 理由：この道具の目的は「読む負担を下げる」こと。情報を足す図は目的に反する。

## 2. スマホで読める大きさ【変えない】

### note の表示幅（2026-09 実測）

| | スマホ（375pt 端末） | PC |
|---|---|---|
| 本文の挿絵の表示幅 | **343pt** | **620pt** |
| 本文の文字サイズ | **16px** | 18px |
| 本文1行の文字数 | 21字 | 34字 |

PC とスマホで本文の文字サイズが違うため、**挿絵の見え方は PC とスマホで1.6倍ずれる**。
基準は小さく見えるほう、つまりスマホに合わせる。

### 制作サイズと縮小率

```
制作 1240px（PC 表示 620pt の2倍）
  → PC     620 / 1240 = 0.500
  → スマホ 343 / 1240 = 0.277   ← この倍率がすべての最小値を決める
```

### 横幅に入れてよい文字数

| 図の横幅に並ぶ字数 | スマホでの見え方 | 本文(16px)との比 |
|---|---|---|
| 14字 | 24.5px | 1.53 |
| 21字 | 16.3px | 1.00（本文と同じ） |
| **28字** | **12.3px** | 0.77 ← **実質の下限** |
| 34字 | 10.1px | 0.63 ← 読めない |

ネットでよく見る 620×620 の正方形インフォグラフィックは、箇条書きがスマホで約8px になっていた。
「ちょっと小さい」と感じるのは正しく、下限を下回っている。

### 挿絵の文字サイズ（`engine/note.css`）

| トークン | 制作 | スマホでの見え方 | 用途 |
|---|---|---|---|
| `--figure-1` | 44px | 12.2px | 注記・凡例・表のセル。**これより小さくしない** |
| `--figure-2` | 58px | 16.1px | 標準のラベル（本文と同じ大きさに見える） |
| `--figure-3` | 76px | 21.1px | 図の見出し・強調 |
| `--figure-4` | 100px | 27.7px | 大きな数字 |

**線は6px以上**（スマホで1.7px）。それより細い線は消える。

### 表は3列まで

`--figure-1`(44px) で1240px幅の表を組むと、外周とセルの余白を引いて1行に約20字。
3列なら1列あたり7字、4列では成立しない。**表は2列が基本、3列ならセルは7字以内。**

## 3. 縦横比

縦横比（高さ÷幅）が **1.6 を超えると、PC で本文の流れを止める**。
1画面を図が占領し、前後の文がつながらなくなる。4:3〜16:9 が目安。
超えたら、項目を減らすか2枚に分ける。

## 4. 色の使い方

ブランドの7役（`tokens.css`）だけで描く。役を増やさない。

| 役 | 使いどころ |
|---|---|
| base（地） | 図の背景。note の本文背景に溶ける色にする |
| surface（面） | 箱・交互行の塗り |
| ink（墨） | 文字と線 |
| muted（淡墨） | 補助線・注記・主役でない棒 |
| **accent（主役）** | **1枚に1か所だけ**。読者の目を最初に止めたい場所 |
| contrast-a / b（対比） | 2つ以上を見分ける塗り |

> 主役が1枚に1か所なのは、「どこを見ればいいか」を図が答えるため。2か所あると、読者は迷う。

塗りの上の文字色は、エンジンが**塗りの明るさから自動で決める**（明るい塗りに白文字、を防ぐ）。

## 5. 避けるもの

- **AI 画像特有の装飾**：発光、炎、金色のグラデーション、過剰な縁取り、色の重ねがけ
- **書き込みすぎ**：隅々まで要素で埋める
- **円グラフ**：スマホの小ささでは角度の差が読めない。構成比は `share`（帯）で描く
- **ぼかし影**：縮小すると汚れに見える。影が欲しいときは「ずらした色面」（`--offset-shadow`）

> 理由：この道具は「画像を AI に丸ごと描かせる」のではなく、「型にデータを流し込む」。
> だから AI が勝手に装飾を足す余地がない。型の側に装飾を増やさないことで、この利点を保つ。

## 6. ヘッドレス Chrome で書き出すときの注意

- `scripts/render.py` は Chrome を2回起動する。1回目で描いて検査し、図の高さを測る。2回目はその高さで撮る。
- Web フォント（Google Fonts）はネットから読む。**オフラインだと代わりの書体で描かれ、字幅が変わる。** 書き出しはネットにつながった状態で行う。
- 検査結果は HTML の中の `#note-fig-lint` に書かれ、Python が読む。
